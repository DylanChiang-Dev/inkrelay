# InkRelay｜墨流

**v0.0.8 · 流程 Skill · MIT**

本版調整長文封面流程：代理依聊天與核准主旨寫提示詞，已選影像模型直接生成標題、畫面與排版，不做程式加字或拼背景。繁體 FB／X 版不要求方圖；只有公眾號版需要圖內有一處能裁出完整 1:1，位置自由、不畫框。

v0.0.5 單稿分發與 v0.0.6 長文模式保留；v0.0.8 以實際封面回饋修正 v0.0.7 的無字、強制共圖與固定中央方區要求，不改短文圖卡／影片流程，也不增加固定渲染器。

同一入口、兩條內容線：長文做自媒體深度文章的素材／來源／論證與核心稿過稿；短文維持一份核心短稿供文字平台使用，圖卡與影片按需派生。不處理論文、作業或正式研究報告。

> 首版提供 Agent 工作流程與製作規格，**不是一鍵生成工具，也不包含固定渲染器**。圖片、影片及預覽依賴使用者環境中已有且獲准使用的工具；沒有工具時，交付已完成的文字與製作規劃並說明缺項。

## 內容線

- **長文**：已有作者與材料 → 查缺項及來源 → 論證骨架確認 → 分節核心母稿 → 局部過稿／交接。核心稿獨立確認；有當篇明確要求時可按所選用途直接生成完整有字封面，不自動配圖、排版、轉短文或影片。
- **短文**：一份核心短稿過稿，供 X 等文字平台使用；圖卡／影片按需。已有稿件直接接續，不因新增長文功能重問身份或重新起稿。
- 判斷依使用者目的，不只按字數或平台；必要時只補問關鍵缺項。學術與正式報告交回專屬流程。

## 長文封面直接生成

代理按聊天、最新全文、核准標題與確認的風格寫提示詞，每篇由已選影像模型一次完成有字封面的整體設計，不用固定背景套版、程式加字、拼背景或重新排版。主體須表達文章核心論點，不只依題材擺道具；使用者要求換風格時優先沿用最新決定，不把米白或保守留白當必需。

- **繁體 FB／X**：完整橫圖，不要求 1:1 或額外方圖。
- **公眾號**：2.35:1 橫圖；圖內任一合適位置能裁出完整 1:1 即可，保留標題與核心畫面，不固定中央、不畫方框。即使本篇公眾號採繁體，也按該用途檢查方區。

兩版可沿用同一視覺方向，但不強制共用同張圖，也不自行增加生成次數；只有取得相應授權才生成選定版本。實際檢視橫圖及公眾號選定方區，不替換 X 個人頁橫幅、不保證各平台預覽，不自動付費重試。草稿試作仍標候選，不補填正文批准。

本版提供工具編排與驗收指引，不捆綁 API runner 或模型；沒有可用工具時說明未生成，不把提示詞冒充已完成封面。

## 短文既有能力

- 接續原始資料、未確認草稿或已核准短文，不重問已有的作者與品牌資料。
- 先完成或沿用一份核心文字，核准後可供使用者手動發 X；只要文字就不要求頭像或視覺形式。
- 視覺分發選一個主形式，另一個按需附帶；明確要雙格式時照要求製作，不強制每篇雙套，或先圖卡後影片。
- 圖卡：3:4、1080 × 1440 PNG，支援單張或封面＋內容頁。
- 依來源選擇觀點、步驟或對照布局；每頁先記錄角色、核心資訊與理由，整組保持同一品牌。
- 用最多五行說明設計選擇，沿用品牌；背景與標記須對應內容，不把通用美學偏好當成禁令。
- 文字影片：9:16、1080 × 1920、30fps，獨立排版、換頁及閱讀停留時間；預設無旁白。
- 可選 X／Twitter 推文卡片式影片：沿用本人真實身份，短稿可單頁全文及置中，不硬拆三頁；沒有實際素材就不放占位。假設藍標樣式須明確說明，不冒充真實帳號狀態。
- 按需求製作繁簡版本；先查正確性，再查實際呈現，優先局部精修，保存問題／修正／重查結果；未檢視項目如實標記待驗證。
- 作者、定位、語言、視覺風格及工具皆可設定；米白科技編輯風只是起步建議，不綁定任何人的品牌。

首版不附背景圖、字型、音樂、API 金鑰或第三方技能，不自動選題、使用付費服務、發布或排程，也不取代既有的長文轉影片流程。

## 安裝

具備讀取 `SKILL.md` 能力的 Agent 可使用本技能。Codex 可在目標專案的 `.agents/skills/` 發現技能；本機可用符號連結維持單一來源，也可在其他環境複製完整的 `skills/inkrelay/` 目錄。

在目標專案根目錄執行以下指令，安裝 **v0.0.8**；若已有同名倉庫或技能，先確認既有內容，不覆寫或刪除：

```sh
(
  set -eu
  if test -e inkrelay || test -L inkrelay ||
     test -e .agents/skills/inkrelay || test -L .agents/skills/inkrelay; then
    printf '%s\n' '同名倉庫或技能已存在，請先確認，不覆寫。' >&2
    exit 1
  fi
  git clone --branch v0.0.8 --depth 1 https://github.com/DylanChiang-Dev/inkrelay.git inkrelay
  mkdir -p .agents/skills
  ln -s "$(pwd)/inkrelay/skills/inkrelay" .agents/skills/inkrelay
)
```

若倉庫已下載於其他位置，將連結來源改為那份倉庫的絕對路徑。請連結整個技能目錄，不只連結 `SKILL.md`，以保留 references 與 UI metadata。技能未出現在清單時，重新載入 Agent 工作階段。

技能命名與發現方式的官方說明：https://developers.openai.com/codex/skills/

## 單稿分發

```text
資料／想法 → 一份核心短文 → 使用者確認
                         ├─ X 等文字平台：使用者手動發布
                         ├─ 圖卡：3:4，按需
                         └─ 影片：9:16，按需
```

保留兩種視覺能力，不把圖卡當必做門，也不預設同時交付所有形式。平台編輯中的修訂需由使用者明確提供，同步回核心稿後才重排選定的派生版本。

## 工具與設定

純文字起稿、分頁與分鏡規劃不需要本倉庫的 npm 或 Python 依賴。實際製作前，Agent 必須確認可用工具及本篇授權範圍：

- 長文封面由已選影像模型直接完成標題與設計；本地工具只做呼叫、存檔、檢查與必要裁切。不捆綁或硬編碼特定模型。
- 短文圖卡及文字影片仍可使用已有排版、截圖或渲染工具，正式正文優先由可控排版處理；長文封面的完整生成方式不自動改寫這條流程。
- 影片可使用既有 Remotion 或其他影片製作工具；本 Skill 不捆綁、不自動安裝這些工具。
- 字型與音樂由使用者提供或在獲准範圍內查核取得；不得把特定平台曲庫的權利延伸至所有平台。
- 影像模型及 API provider 沿用使用者設定，不硬編碼、不自行替換；有費用的呼叫須確認授權。

作者名稱、定位、主要語言、視覺樣板、平台及輸出形式可從專案資料或對話取得，不必為使用本 Skill 建立特定設定檔。缺少資料時，只詢問會影響本篇工作的必要項目；示例不是作者資料。
