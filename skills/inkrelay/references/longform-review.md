# 長文過稿檢查

只處理稿件需要的檢查，不把核心母稿審閱擴張成期刊審稿、配圖或發布。先核對最新作者決定與已有來源紀錄；已確認事項不重問。

## 四個檢查面向

1. **論證**：問題、各節主張與結論是否接續？重要斷點按 [論證推進](writing-craft.md#論證推進) 找到缺前提、錯位或冗段；已順暢的段落不加無用橋接。是否把關聯、單一案例或廠商宣稱寫成普遍因果？反例與限制有沒有被刪掉？
2. **證據**：承重數字、技術能力、時間與效果能否回到已取得原文？主張是否超出來源？引用定位未知或無法取得時保留待查，不假稱核對完成。
3. **作者**：第一人稱判斷、反應、例子與研究目標是否有使用者材料？文風問題按 [作者表達](writing-craft.md#作者表達) 指出位置與效果，尊重既有偏好，不用句型判定作者身分。是否擅自新增親測、經歷、情緒或成熟批判？已有聲音與公開邊界是否保持？
4. **讀者**：必要時先讀 [閱讀入口](writing-craft.md#閱讀入口)，單獨檢查實際標題與首段。文章是否交代必要定義、前提與轉折？讀者可能在哪裡誤解或不知道為何重要？檢查必須從稿件出發，不自創本文沒有的主張。

本次涉及標題或閱讀承諾時，按 [標題與內容承諾](writing-craft.md#標題與內容承諾) 對回正文；精確文字已核准時只指出問題並提出待採用建議，不擅自換標題，也不自動製作封面。

對最重要的問題列出 **位置、問題、依據、建議修正**，區分必改、作者取捨及可能的讀者誤解；局部修正後重查相關論證，不自行重寫整篇或偷偷換立場。

本代理可以作讀者視角自檢，但這不是獨立讀者測試。沒有實際執行就不標「獨立測試通過」；子代理、外部讀者、付費工具或未公開稿件的外傳都需相應授權，不因借用上游技能而自動派出。

## 核心稿交接

交付核心文稿與必要來源，內部清單另放；如實說明已完成、待確認與未解項目。核心稿批准不代表平台稿、來源補查、封面、配圖、短文或影片已完成或已取得製作授權；明確要求封面時讀 [長文橫向封面](article-cover.md)，只執行已授權項目，不重問已包含在本篇指令中的生成授權。
