# InkRelay 行為驗證

本文件給維護者更新 Skill 時使用，不是每篇文章必經程序，也不是作者真偽或流量評測。日常任務仍只載入相關寫作指引。測試只用已授權、可公開或明確標示的虛構材料；虛構試稿不能當作真實實作成果。

## 先固定可觀察的任務

記錄基準快照、候選快照、材料與使用者請求，為每案列出應完成的工作及不能發生的關鍵失敗。檢查實際輸出與工具動作，不要求固定句子、標題、段數或隱藏推理。期待表達可以多樣，但作者原意、證據範圍、局部修訂與授權必須守住。

案例應同時有需要改善的稿件、原本已好的對照、資訊／工具不足，以及相似但不應啟動完整流程的請求。留出材料在候選穩定後才使用，不用它反覆調參；修訂後再看舊能力是否退化。案例數與代價按變更風險決定，不把本次樣本數變成永久門檻。

## 執行與評估分離

在有明確授權與可用代理時，用新的執行上下文完成基準與候選的相同請求，只提供指定 Skill、原始任務及必要材料，不提供理想答覆、疑似缺陷或評分條件。兩個版本不得共用前一輪試稿記憶。按需讀 reference 的實際行為也記錄下來。

評估者取得原請求、驗收條件與去除版本路徑的輸出，先判斷各自完成什麼，再比較可定位的改善和退化；版本對照在評估後才揭示。匿名化不能保證評估者猜不出版本，樣本與模型有限也不能推成普遍效果。

沒有獨立執行者或評估者時，改做明確標為自檢／人工走查的驗證，不假稱盲測。不得為測試擅自外傳私人稿件、叫付費 API、生成媒體、建庫或安裝工具。

## 保留證據與處理失敗

保存請求、實際答覆、確實讀取的檔案、工具動作、模型／環境能取得的資訊、判定依據與未執行項目；來源快照須可還原，不能只記「最新版」。測試規格可公開，私人輸入、帳號、憑證與未公開文稿不能打包進 Skill。

失敗先分清是指引衝突、輸入缺項、工具限制、驗收條件不合理或執行波動，再做最小修正。重跑受影響案例並留原失敗紀錄。虛構經歷／證據／成果／授權／成品、越界改稿或外部動作是關鍵失敗，不以文筆流暢抵消。

## 如實報告完成層次

- **結構檢查**：入口欄位、引用、版本及可載入性。
- **文件走查**：逐案核對流程是否有適用指引，不等於模型已執行。
- **實際試稿**：保留指定版本的真實生成答覆與工具動作。
- **獨立評估及回歸**：評估者對輸出作判斷，留出與原能力另有結果。

這些證據各自報告，不把其中一項當成下一項已完成，也不稱測過少量虛構案例就保證真實文章、模型、媒體或平台效果。確定性結構檢查可執行 `python3 tests/validate_structure.py .`；此工具只接受本倉庫已使用的 YAML 子集與本地引用，不是通用 YAML 驗證器或行為評測。
